# 生产资料归档合规性评审

## Overview

对硬件产品/单板的生产资料归档包做结构化合规检查：确认评审类型（初次归档/变更），逐项执行检查清单，交叉核对文件一致性，最终用脚本生成纯问题清单 Excel 报告（只列检查出的问题项，不做结论、不分严重度、不给整改意见）。

## 评审类型确认（必须首先执行）

收到评审请求后，**先以提问框形式向用户确认评审类型**，再开始任何检查：

- **初次归档评审**：首次归档，无历史版本参照
- **变更评审**：已归档产品/单板发生工程变更（ECO/ECN/改版/升版）后重新归档

若用户请求中已明确说明评审类型（如明说"做变更评审"），仍需以提问框确认一次，默认选中该类型。

## 评审流程

### Step 1 — 建立文件索引

1. 递归列出归档包内全部文件（含子目录）
2. 识别每个文件的编码、版本号、日期（从文件名、文档属性或正文提取）
3. 变更评审时：建立新旧版本配对索引（同编码不同版本配对）

分类不确定的文件列入"其他"并在报告中说明，不强行归类。

### Step 2 — 加载检查清单

- 初次归档评审 → 读取 `references/initial-review-checklist.md`
- 变更评审 → 读取 `references/change-review-checklist.md`（变更单核查 + 新旧对比两部分都执行）

### Step 3 — 逐项检查

按清单逐项检查，**只记录检查出的问题项**，每条记录：

| 字段       | 说明                                   |
| -------- | ------------------------------------ |
| id       | 清单编号（如 B1-04）                        |
| category | 类别（比如整机BOM/单板BOM/Gerber/规格书/齐套性/变更单） |
| item     | 检查项描述                                |
| evidence | 问题描述：具体文件名、位号、单元格位置、差异内容             |

检查要求：

- BOM（Excel/CSV）用表格方式读取（sheet 技能或 pandas），逐行核对，禁止抽样过半
- Gerber 只做文件级检查：层文件齐套性、命名、版本标识、配套钻孔/贴片坐标文件是否齐全；不解析图形数据
- 规格书（PDF/Word）提取版本、修订记录、技术指标章节做交叉核对
- 交叉一致性矩阵（初次归档清单末尾）必须全部核对
- 每条问题必须有具体证据（文件名+位置），禁止无证据报问题

### Step 4 — 生成报告

1. 将问题项汇总为 findings JSON（结构见 `scripts/generate_report.py` 文件头注释）
2. 执行：

```bash
python scripts/generate_report.py --project "产品/单板名" --type initial|change --json findings.json --out 评审报告.xlsx
```

1. 报告为单 Sheet 纯问题清单：`问题清单`（序号/检查项编号/类别/检查项/问题描述），不做结论、无严重度、无整改建议，同一个表格框里多个问题要分行并按照序号顺序排列，清晰呈现各个问题
2. 用 present_files 将报告交付给用户

## 公司规范融合

公司规范以快照形式沉淀在 `references/company-spec.md`，文件头必须注明版本号与生效日期。机制：

1. 该文件存在时，评审优先按公司规范检查；通用清单中对应项以公司规范为准，问题描述中引用规范条款号
2. 公司规范未覆盖的项，按通用清单执行
3. 该文件不存在时，通用清单即为完整评审依据
4. 用户在评审现场提供了更新的规范文本时，以现场版本为准执行本次评审，并在报告中记录实际使用的规范版本
5. 规范正式升版后：更新 company-spec.md 的内容与版本头，重新打包分发，保证全团队规范版本一致

findings JSON 中可用 `spec_version` 字段记录本次评审依据的规范版本，报告表头下方单列一行展示。

## Resources

### scripts/generate_report.py

Excel 问题清单生成器。输入 findings JSON，输出单 Sheet 问题清单。依赖 openpyxl（缺失时先 `pip install openpyxl`）。

### references/initial-review-checklist.md

初次归档评审检查清单：齐套性、整机 BOM、单板 Gerber、单板 BOM、规格书五组检查项 + 交叉一致性矩阵。

### references/change-review-checklist.md

变更评审检查清单：变更单完整性、版本升级合规、新旧版本 diff、变更验证与追溯四组检查项。

### references/company-spec.md

公司归档规范快照（默认为待填模板）。填入公司规范后评审以公司规范优先，并支持问题描述引用条款号。
