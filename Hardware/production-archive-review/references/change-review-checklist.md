# 变更评审检查清单

---
version: 1.0.0
---

适用场景：已归档产品/单板发生**工程变更**（ECO/ECN）后，对变更资料做合规性检查。

变更评审 = 变更单闭环核查 + 新旧版本文件对比。检查结果只记录问题项。

---

## 1. 变更单完整性检查

| #    | 检查项                                                                                                                                                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C-01 | 变更单编号唯一，关联原归档版本号与新版本号                                                                                                                                                                                                                                                                 |
| C-02 | 变更原因明确（缺陷整改/降本/器件停产替代/工艺优化/客户要求）                                                                                                                                                                                                                                                      |
| C-03 | 变更实施日期/切换点明确（在制品、库存、在途物料的处理方案）                                                                                                                                                                                                                                                        |
| C-04 | 变更期限如果是临时，要填写生产任务单号                                                                                                                                                                                                                                                                   |
| C-05 | 变更原因要写分类，主要有<br />1）硬件设计变更(适用于 PCB、PCBA 等变更)<br />2）结构设计变更(适用于结构件等变更)<br />3）整机设计变更(适用于包装、线缆、辅材等变更)<br />4）软件设计变更(适用于软件迭代、软件问题解决等变更)<br />5）测试设计变更(适用于测试文档、测试问题解决等变更)<br />6）工艺文件变更(适用于工艺流程、工序等变更)<br />7）质量文件变更(适用于质检文件等变更)<br />8）文件变更(适用于文件错别字修改等变更)<br />9）其他变更(除上述情况包含不了的其他情况变更) |
| C-06 | 变更内容里变更前和变更后要对应说明                                                                                                                                                                                                                                                                     |
| C-07 | 审批签署栏里面不用填写内容，如果空白不是问题，不用提出                                                                                                                                                                                                                                                           |

## 2. 新旧版本对比检查（文件 Diff）

对比方式：新旧两版文件逐项对比，输出差异清单后再逐条核对。

| #    | 检查项                                      |
| ---- | ---------------------------------------- |
| D-01 | BOM diff：所有差异行项均能对应到变更单范围，无"夹带变更"        |
| D-02 | BOM diff 中的器件替换：位号、封装、用量与变更单描述一致         |
| D-03 | 变更前后的内容要在变更单中有对应说明                       |
| D-04 | 对比变更前后的2个文件夹所有文件的差异，包含但不限于文件的名称、日期、内容、数量 |

## 3. 变更验证内容

在变更单完整性检查、新旧版本对比检查后，读取 `references/initial-review-checklist.md`对变更的文件做审查，如果未涉及项或不存在目标文件则在问题描述里写“无对应文件未涉及”

---

## 变更评审执行流程

1. 读取变更单，确认变更范围与受影响文档清单
2. 建立新旧版本文件对照索引（编码 + 版本号配对）
3. 按 C 组清单核查变更单完整性
4. 对变更前后文件执行逐项 diff
5. 按 D 组清单核对差异项
6. 汇总问题清单，调用报告脚本生成 Excel 问题清单报告，同一个表格框里多个问题要分行并按照序号顺序排列，清晰呈现各个问题
