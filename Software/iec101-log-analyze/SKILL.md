# IEC 60870-5-101 报文日志分析

## 触发场景

- 用户给出 101 报文日志（文本或**截图**），要求逐条说明 / 定位异常 / 统计耗时。
- 光伏、配电、水务等远动监控平台的"总召慢""通信异常""丢帧"类排查。

## 第 0 步：取证（截图日志必做）

文字密集的截图直接 Read 分辨率不够，必须放大：

```python
from PIL import Image
import numpy as np
im = Image.open(path).convert('RGB')
# 1) 行投影定位每一行文本
a = np.array(im.convert('L'))[:, 300:1150]
rowdark = (a < 110).sum(axis=1)
# 扫描 rowdark>2 的连续段即为行，取中心 y
# 2) 按 (y0,y1) 裁 20px 高、x 覆盖报文列，放大 6~12 倍后 Read
c = im.crop((295, y-10, 700, y+10)); c = c.resize((c.width*6, c.height*6), Image.LANCZOS)
```

- **必须逐行裁剪放大后再 Read**，不要相信一次性整体 Read 的字节（常见把 `0B` 读成 `08`、`F0` 读成 `70`）。
- 判定每行方向：按行统计箭头像素与报文文字的 RGB 均值，红/蓝分开（`R-B>30` 为红，`B-R>30` 为蓝）。结论通常是：**日志工具按控制域 bit7 着色**，个别帧颜色会与语义方向相反，需在报告中说明，不要当成故障。

## 第 1 步：帧格式（先把长度对齐，再谈语义）

```
固定帧：10 | C | A(2B,LE) | CS | 16
可变帧：68 | L | L | 68 | C | A(2B,LE) | ASDU | CS | 16
CS = 从控制域到 ASDU 末尾所有字节算术和 mod 256
L  = 控制域 + 地址域 + ASDU 的字节数（不含 CS 与 16）
```

**用 CS 反推切分是否正确**：本设备 CS 校验通过的那一版切分才是对的。

### 本类设备的 ASDU 结构（已实测确认）

```
TI(1) | VSQ(1) | COT(2) | CA(2,LE) | IOA(2,LE) | 信息元素 | QOI
```

- **关键坑**：`CA(2B)+IOA(2B)` 与 `CA(1B)+IOA(3B)` 的总长度相同，长度校验**区分不出来**。  
  用**跨帧 IOA 是否连续**判别：若相邻帧 IOA 差值 = 对象个数（如 0x4001→0x4030，差 0x2F=47），则 CA=2B/IOA=2B 正确；若差值 = 对象个数×256，说明误把 CA 当 1 字节。
- 长度核算：单点帧 `1+1+2+2+2+1×N`（N=SIQ 字节数）；短浮点帧 `1+1+2+2+2+5×N`（4B 浮点 + 1B QDS）。

### 常用取值

| 字段            | 值                                                                                              | 含义           |
| ------------- | ---------------------------------------------------------------------------------------------- | ------------ |
| TI 0x01       | 单点信息 M_SP_NA_1                                                                                 | 1B/点         |
| TI 0x0D       | 短浮点数测量值 M_ME_NC_1                                                                              | 5B/点（浮点+QDS） |
| TI 0x64 (100) | 站总召唤 C_IC_NA_1                                                                                 | QOI=0x14(20) |
| TI 0x6A (106) | 延时获得命令 C_CD_NA_1                                                                               | 2B 毫秒参数      |
| COT           | 1/2/3=周期/背景/突发，6=激活，7=激活确认，10=激活终止，20=响应站总召唤                                                   |              |
| VSQ           | bit7=SQ，bit0-6=对象个数                                                                            |              |
| 控制域           | 0x40/0xC0 复位远方链路；0x49/0xC9 请求链路状态；0x0B/0x8B 响应链路状态；0x00/0x80 肯定确认；0xF3/0x73/0xD3/0x53 发送确认用户数据 |              |

**控制域第一字节 bit 分配（非平衡，用于判定方向）**：bit7=PRM（1=启动站/主站，0=从动站/设备），bit6=FCV，bit5=FCB/DFC，bit4=保留，bit3~0=FC 功能码。

- `00` → PRM=0, FC=0 → **从动站（设备）发出的肯定确认**，即最典型的 `10 00 01 00 01 16`
- `80` → PRM=1, FC=0 → **启动站（主站）发出的肯定确认**，用于应答设备上送的用户数据帧，即 `10 80 01 00 81 16`
- **易混点**：这是**链路层**确认（固定帧，无 ASDU）；与应用层 `COT=7 激活确认`（可变帧，带完整 ASDU）完全不是一回事，报告里必须分开讲。

## 第 2 步：按阶段分段（101 会话固定四段）

1. **建链**：请求链路状态 → 响应链路状态 → 复位远方链路 → 肯定确认（可能两轮）
2. **总召唤**：召唤命令(激活) → 肯定确认 → 召唤命令(激活确认) → 肯定确认 → N 帧数据(每帧一个 ACK) → 召唤命令(激活终止)
3. **参数类命令**：如延时获得命令（激活/激活确认/突发）
4. 统计每段耗时、每帧间隔

## 第 3 步：必查异常点

- **帧间隔 >> 单帧传输时间** → 瓶颈在设备组帧节拍，与空口速率无关（算有效 bps 与空口速率对比，给出利用率）
- **原帧短时间后重发**（≈T1） → 链路层 ACK 丢失，空口丢包/时延抖动
- **测得值全 0 / QDS ≠ 0x00** → 数据无效或未初始化，需核对点表与信号接入
- **激活参数与激活确认参数不一致** → 设备回显/重算逻辑问题
- **同功能控制域出现 0x4x/0xCx 两形态** → bit7 的 DIR/FCB 定义需向厂家确认，不要直接判故障
